## Environment

`package.json` has no preview script and alchemy 2.0.0-beta.81 has no preview command, so
nothing served the production build locally. Lighthouse and the traces ran against
`bun run dev` (Vite dev server under `alchemy dev`, `http://localhost:4692`, CPU 1x, no network
throttling) through the `chrome-devtools` CLI started with `--isolated=true`, because the MCP
server's own Chrome profile was held by another session. Accessibility, SEO and CLS depend on
the rendered DOM and hold for the production build too. LCP here is the dev server's on
localhost and is not the number users get, so `## Best so far` carries no LCP. The production
build was measured by `bun run build` alone, under `## Client bundle`.

`/profile` was reached as the dev user, which the dev build's email-and-password sign-in
creates on the first click of "Sign in With Google".

## /
- **a11y · landmark-one-main**: the document has no `<main>` landmark, 1 document · impact moderate · fix: the root layout's content wrapper becomes `<main>`
- **a11y · target-size**: react-grab's "Copy element" toolbar button is 14×14 px, 1 element · impact serious · no fix: the toolbar loads only under `import.meta.env.DEV`, so the production build has no such element
- **SEO · meta-description**: the document has no `<meta name="description">` · fix: a description in the root route's `head()`
- **LCP**: element `pre.font-mono` (the setup command block), TTFB 15 ms, resource load 0 ms (text, no resource), render delay 48 ms
- **CLS**: nothing shifted
- **Render-blocking**: `/@tanstack-start/styles.css` blocked 5 ms (the dev server's stylesheet route; the production build inlines a `<link>` to the built CSS)

## Client bundle

`bun run build` on the measured commit printed "Some chunks are larger than 500 kB after
minification": `dist/client/assets/index-*.js` was 601,436 bytes minified. A source-map
breakdown put react-dom at 30% of it, effect at 16%, `@tanstack/router-core` at 10%, sonner at
6% and `@tanstack/query-core` at 5%. After `vite.config.ts` gave the client build two
`codeSplitting` groups (`react`: react, react-dom, scheduler; `effect`), the build prints no
warning and the chunks the entry loads on every page are:

| Chunk | Minified (bytes) | Gzip (bytes) |
|---|---|---|
| index | 328,044 | 107,407 |
| react | 189,745 | 59,003 |
| effect | 97,291 | 31,459 |
| utils | 27,858 | 8,904 |
| index.css | 45,056 | 8,606 |

The four script chunks total 206,773 bytes gzip before a page's own route chunk (958 to 48,278
bytes minified). The split moves no bytes out of the first load: `/` desktop measured after it
matches the after-fix table below (A11y 96, SEO 100, best practices 100).
