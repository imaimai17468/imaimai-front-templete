# Cross-site scripting

Draws on chapter 8 (クロスサイトスクリプティング).

Cross-site scripting happens when a value from outside the code reaches a place where the browser parses it as markup, script or a URL instead of showing it as text. Whether the value was stored first, reflected from the request, or read by client code only changes the route it took, and one bug can be all three. What a reviewer follows is one line per value: where it came from, where it is written into the document, and which parser reads it at that spot. A script that runs there runs as this origin, with the signed-in user's cookies attached to every request it makes, so `HttpOnly` on the session cookie limits what it can read and nothing about what it can do.

## Where the decision lives here

Rendering is React inside TanStack Start, on the server for the first document and in the browser after that. A value written as a JSX child or as an ordinary attribute value is escaped on the way out: a profile name of `</script><b>xss-marker</b>` rendered on `/profile` as `&lt;/script&gt;&lt;b&gt;…` in the name input's `value`, with no `<b>` element in the page. The escaping covers those two positions only. Three places sit outside it:

- **`dangerouslySetInnerHTML`**, which hands a string to the HTML parser. `git grep -n dangerouslySetInnerHTML -- src` found no use on 2026-09-30.
- **URL attributes** (`href`, `src`, `action`, `formAction`). Escaping keeps a value inside its quotes and does not judge the scheme it names. The one data-driven URL today is the avatar `src`, which `CurrentUserReader` in `src/shared/gateway/user/read.ts` builds either with `avatarUrlForKey` (`src/lib/avatar-url.ts`, a fixed path plus an encoded key) or by passing the `image` column through `httpsUrl` (`src/lib/https-url.ts`), which lets only an absolute `https:` URL through.
- **The dehydrated query cache.** `setupRouterSsrQueryIntegration` in `src/router.tsx` serializes the queries a server render filled into inline `<script>` elements, and the root loader in `src/routes/__root.tsx` fills `currentUserQueryOptions` on every page. The same marker name appeared inside that script as `"\x3C/script>\x3Cb>xss-marker\x3C/b>"`, so it did not close the element. That was observed on this version of the router; the escaping belongs to the framework's serializer, which this reference did not open.

The document's `Content-Security-Policy` is `frame-ancestors 'none'` and carries no `script-src`, so no browser-side rule stops an injected script today. `browser-headers.md` covers what adding one would take.

## Checks

**No string reaches an HTML sink.** Run `git grep -n -e dangerouslySetInnerHTML -e innerHTML -e outerHTML -e insertAdjacentHTML -e 'document.write' -- src`. `src/shared/ui/` is included, because shadcn copies component source there. The code is right where there is no hit, or where each hit's value is a literal in that file, or passes a maintained sanitizer with an explicit allow list of elements and attributes before the sink. It is wrong where the value is a row, a server function result, a search param or anything a user typed. A hand-written tag filter, such as a regex that removes `<script>`, counts as wrong: event attributes, SVG and URL schemes pass it.

**A URL attribute built from data is checked for its scheme.** Run `git grep -n -e 'href={' -e 'src={' -e 'action={' -e 'formAction={' -- src` and trace each value to where it was made. Right is a literal (the links in `src/routes/index/-components/home-content.ts`), a path the code assembles itself (`avatarUrlForKey`), or a value that passed `httpsUrl`. Wrong is a column, a search param or a server function result reaching the attribute directly. The `image` column is user-controlled, and more than the Google provider writes it: Better Auth's `POST /api/auth/update-user` accepts `image` in its body and stored `javascript:alert(1)` from a signed-in dev session. `CurrentUserReader` reads it through `httpsUrl`, whose doc comment in `src/lib/https-url.ts` says it covers that one read, so a new read of `users.image` carries the same filter. Better Auth's own `GET /api/auth/get-session` returns the stored `image` unfiltered, so a component that starts reading the session through `authClient.useSession` takes the raw value.

**Data put into a script stays data.** Search `head()` in `src/routes/` for a `scripts` entry, and the components for a `<script>` whose body is built from a value. Right is none, or data handed over only through a loader or the query cache, which the reproduction below shows escaped. Wrong is a value interpolated into script text, including `JSON.stringify(value)` placed in `dangerouslySetInnerHTML`, because `JSON.stringify` leaves `</script>` as it is and the HTML parser ends the element there.

**What a loader returns ends up in the page source.** The dehydrated cache is readable by anyone who can read the document, and by any script running in it. Read what each loader and each query filled during SSR returns. Right is the fields the page shows. Wrong is a row returned whole, such as a column the UI never displays, because the HTML carries it whether or not a component reads it.

**Every page that shows the value is checked, not only the one that saves it.** A name saved on `/profile` is also rendered by `UserMenu` (`src/shared/components/header/user-menu/user-menu.tsx`) in the dropdown every page's header opens, and as the avatar's `alt` and first letter. A new view of stored text, such as an admin list, an e-mail body or an error page, is a new place to check with the same test.

**Validation and escaping are not the same step.** `UpdateUserSchema` in `src/shared/entities/user/index.ts` limits the name to 1 to 50 characters and says nothing about what the name may contain, which is right: the value is stored as typed and escaped where it is written out. Replacing `<` with `&lt;` before storing it corrupts the value everywhere it is not HTML and is escaped a second time by React.

## Reproduce locally

Set a value that looks like markup and read it where it is rendered. On `bun run dev`, sign in, open `/profile`, and save the name `</script><b>xss-marker</b>`, which fits the 50-character limit. Reload `/profile` and open the page source. The name appears as `&lt;/script&gt;&lt;b&gt;xss-marker…` in the input's `value` and as `\x3C/script>…` inside the `$R` stream script, and, with the user menu in the header opened, DevTools' Elements panel shows no `<b>` element in the menu or the form: the escaping holds. A bold `xss-marker` anywhere on the page, or a `<b>` element in Elements, means the value was parsed as HTML. Finding the marker nowhere means the save failed or the page does not show the name, so the step proved nothing.

For the URL attribute, use an account with no uploaded avatar, because an `avatarKey` takes precedence over `image` and the step would then prove nothing. With that session's cookie, send `POST /api/auth/update-user` with `Origin` set to the dev URL, `Content-Type: application/json`, and a body whose `image` is a `javascript:` URL. Then request `/` with the same cookie and find `avatarUrl` in the `$R` stream script, because the avatar `<img>` is added by the browser after hydration and is absent from the server's HTML. `avatarUrl:null` means `httpsUrl` dropped the value. The URL itself appearing there means an unchecked scheme reaches `src`. Repeat with an `https://` image first, which should come back unchanged; if it does not, the filter or the request is broken and the `javascript:` result means nothing.

## Fix and pin

Render stored and requested text as a JSX child or an ordinary attribute and let React escape it. Where a feature must accept HTML, sanitize it with a maintained sanitizer and an explicit allow list at one place that every render path goes through, and record which code vouches for the value. Give every URL built from data a pure filter that decides its scheme, as `httpsUrl` does.

Pin a URL filter with one row per scheme, accepted and rejected, as `src/lib/https-url.test.ts` does for `https:`, `http:`, `javascript:`, `data:` and a protocol-relative URL. Pin a component that shows user text by rendering it with a markup-shaped value and asserting in one `toStrictEqual` that the text is shown and that no element was created from it, such as `{ text: value, injected: null }` for the text content and `container.querySelector("b")`. Keep a row with ordinary text containing `<`, `&` and quotes, such as `1 < 2 && "a"`, so a fix that rejects those characters fails as loudly as the hole.
