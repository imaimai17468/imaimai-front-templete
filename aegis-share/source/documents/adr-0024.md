# 0024. One definition of "lands a commit"; the gate's markers are not writable from Bash

- Status: accepted
- Date: 2026-07-30

## Context

An adversarial audit on 2026-07-30 found three ways past the commit gate ADR-0013
established. All three predate that day's work on *what the stamp certifies*, so
the gate was being made more meaningful while remaining walkable.

1. **A metacharacter against the command word skipped the gate entirely.** Both
   `pre-bash-guard.sh` and `post-bash-stamp-consume.sh` required the character
   before `git` to be start-of-string or one of `;&| `. Verified: `(git commit)`,
   `$(git commit)` and the backtick form matched none of those and were never
   examined — no stamp required. `(cd sub && git commit)` *was* caught, but only
   because the space after `&&` happened to satisfy the class.
2. **The two guards had drifted, and the drift was a hole.** The consume side
   required whitespace after `commit`; the gate accepted any `\bcommit\b`. So
   `git commit;true` was gated on the way in and **not** recognised as a landed
   commit on the way out, leaving a live stamp to authorise the next, unreviewed
   change — precisely the hole `post-bash-stamp-consume.sh` exists to close
   (ADR-0019). The two patterns carried a comment asking the next editor to "keep
   the two patterns in step". That is an instruction, and this repository has
   concluded three times that instructions are not mechanisms (ADR-0001, ADR-0013,
   ADR-0019).
3. **The stamp was forgeable with one allow-listed command.** `Bash(touch:*)` is in
   `permissions.allow` and nothing protected the marker files, so
   `touch .claude/.review-stamp` satisfied the gate with no review at all. The only
   thing standing against it was a sentence in the `review-diff` skill saying not
   to. Guard 1 in the same file already applies a lexical guard to the env files for
   exactly this reason — "allowed Bash readers could walk around `permissions.deny`"
   — and that reasoning was never extended to the gate's own state.

## Decision

**One shared definition of the shape.** `lib-commit-shape.sh` holds
`command_lands_a_commit()`, sourced by both hooks. Statement separators and
grouping characters become newlines and the test runs per line, so a metacharacter
against `git` cannot hide it; backslash-newline is joined first, because it is a
continuation rather than a separator; only horizontal whitespace is squeezed after
that, because squeezing all whitespace would rejoin the statements just split and
make `git status; echo commit` match. `commit` stays a whitespace-delimited word so
`git log --grep=commit` is not a commit.

Sharing is the point, not the pattern. Two hooks answering the same question with
two hand-written regexes is a drift waiting to happen, and the drift is silent: the
gate keeps blocking, so nothing looks broken while the stamp quietly outlives its
batch.

**The gate's markers are refused from Bash, and denied to `Write`/`Edit`.** A new
Guard 3 in `pre-bash-guard.sh` refuses any command naming `.review-stamp`,
`.finder-done`, `.finder-hash` or `.pair-ok`; eight `permissions.deny` entries cover
the two tools a Bash guard cannot see. Reads are refused along with writes because
separating them lexically needs a verb list and a verb list rots — `ls -la .claude/`
shows every marker's state without naming one, so no diagnostic is lost.

`scripts/test-bash-guard.py` and `scripts/test-review-gate.py` pin the shapes listed
below on the gate and consume sides respectively, so the two can no longer disagree
without a test failing. "Every shape" is deliberately not claimed — the review of
this change found three the first version missed, and the honest statement is a list
plus a named residual, not a universal.

The reviewed set: the plain form; a metacharacter glued before `git`
(`(…)`, `$(…)`, backticks, brace group, conditional); an operator glued after
`commit`; `git add -A && …`; a backslash line continuation, including one splitting
the verb itself; a quoted verb (`git 'commit'`); and `git${IFS}commit`. Bash removes
quotes and performs `${IFS}` splitting before dispatch, so those two really do
commit; the normalisation strips quotes and expands the braced `${IFS}` for that
reason. `$IFScommit` needs no handling — bash reads it as one undefined variable
name and no commit runs.

## Alternatives considered

- **Fix the two regexes separately and keep the "stay in step" comment**: rejected.
  That comment is the thing that failed; the hole existed *because* the two were
  maintained by hand against a request to remember.
- **A verb allow-list so marker reads stay possible**: rejected. It is an
  enumeration, so it rots, and it would have to be right about every file-creating
  verb. `ls -la .claude/` covers the real need.
- **Parse the command properly instead of normalising**: rejected as
  disproportionate. A shell parser in a hook is a large dependency for a check whose
  honest ceiling is "raise the bar", and the guard already over-matches in the safe
  direction.
- **Rely on `permissions.deny` alone for the markers**: rejected — `deny` governs
  tools, and `touch` is a Bash command. Guard 1 exists because of that exact gap.

## Consequences
 
- Every shape in the reviewed set above now both blocks when unstamped and consumes
  the stamp when landed, and neither behaviour can drift from the other without a
  test failing. The consume side additionally truncates at the first heredoc
  operator: prose in a heredoc body reading `git … commit` was enough to delete a
  stamp the review had earned, and writing a document through a heredoc is routine
  here. The gate side keeps the heredoc, staying the stricter of the two.
- **Two named residuals, rather than a generic disclaimer.** *Visible but unparsed
  text* is now handled for the shapes above; what remains is *invisible state*. A
  git alias (`alias.ci=commit`) makes `git ci -m x` land a commit with the word
  absent from the command entirely — undetectable without resolving aliases at hook
  time, which is the "parse the command properly" direction rejected above. And any
  further quoting or expansion trick not in the reviewed set is unhandled by
  construction. Naming these beats the earlier wording, which asserted "every shape"
  and was false within one review.
- **A cost accepted knowingly.** Stripping quotes means a git subcommand whose quoted
  argument is literally `commit` — `git show 'commit'` for a ref of that name — now
  reads as a commit. On the gate side that re-runs a check that passes; on the
  consume side it costs one unnecessary review. Both are cheaper than the confirmed
  bypass they close.
- **Naming a marker in a Bash command now fails**, including in prose. That is the
  same friction Guard 1 already imposes for the env files, and it bit repeatedly
  while writing this change: several diagnostic commands had to be rephrased, and a
  `grep` for the deny entries was refused for quoting a filename. Annoying, and the
  safe direction.
- **Still lexical, therefore still defeatable.** An agent that decides to cheat can
  obfuscate the path or the command. What this buys is that forging is no longer
  allow-listed and silent — it requires deliberate evasion, visible in the
  transcript. Same honest framing as ADR-0017 for secrets: defense-in-depth, not a
  boundary.
- The gate now rests on three mechanisms rather than one instruction, but the
  ordering lesson stands on its own: four review cycles went into making the stamp
  certify the right event while `(git commit)` walked past the gate that requires it.
  Auditing what a gate *enforces* should precede refining what it *means*.
