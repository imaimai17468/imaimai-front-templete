# 0026. The `.cursor/` and `.codex/` adapter mirrors are removed; `deploy-adapters` is not run

- Status: accepted (amended by 0031)
- Date: 2026-07-31

> **Note (ADR-0031, 2026-08-07):** `.cursor/rules/` exists again — as
> file-level symlinks into `.claude/rules/`, never copies. A symlink cannot
> drift, which is the failure this ADR removed. The deletion of *copies*, the
> `deploy-adapters` ban, and the Consequences below stand; the sentence that
> Cursor sessions "get no Aegis instructions" no longer holds. The
> `deploy-adapters` warning itself moved from AGENTS.md to
> `.claude/rules/aegis.md`.

## Context

`npx @fuwasegu/aegis deploy-adapters` writes the Aegis process instructions into
one file per editor. Run on 2026-04-30 (`deaa1d8`), it produced
`.cursor/rules/aegis-process.mdc` — a full copy of AGENTS.md's
`aegis:start`/`aegis:end` block, which Cursor loads as an always-on rule — plus
mirrors of three aegis skills under `.cursor/skills/` and `.codex/skills/`.

Those copies then sat untouched for three months while the block they mirror was
edited repeatedly. By 2026-07-31 the Cursor copy said `intent_tags` was
"recommended" in one step and "optional" in another, while the block required it
and `pre-aegis-compile-guard.sh` blocked any call that omitted it. It also still
carried the vendor's placeholder path example from another codebase. Nothing
detected the drift: no gate reads those files, and nothing in the repository even
recorded that they were copies.

The same day, running the command to resolve the "adapter templates may be
outdated" notice that ends every aegis response overwrote the block itself with
the vendor template — reverting that day's edits, substituting the foreign path
example, and appending a second copy of the block to `CLAUDE.md`, which ADR-0008
keeps at `@AGENTS.md` alone. It reported each file as created/updated/unchanged
and asked nothing first. The damage was reverted before any of it was committed.

## Decision

**Delete `.cursor/` and `.codex/`, and do not run `deploy-adapters`.**

The rules have one home: AGENTS.md, loaded every session. This is ADR-0008's
decision item 1 applied to a copy that ADR-0008 did not anticipate, and the same
reasoning ADR-0021 used to delete `docs/adr/` — two copies under two update
disciplines means one of them is wrong, and the wrong one is whichever a reader
happens to open.

Reconciling the copies instead was rejected: reconciliation would have been
correct on the day it was done and stale again at the next edit to the block, and
the three months just spent proves the discipline does not hold. Nothing here can
detect the drift, so the only durable form is not having the copy.

AGENTS.md carries the operational half of this — a section placed deliberately
*outside* the managed block, because anything written inside it is what the
command discards.

## Alternatives considered

- **Reconcile `.cursor/rules/aegis-process.mdc` and keep it**: rejected, above.
  It also leaves `deploy-adapters` a step someone will eventually take.
- **Keep the mirrors and add a gate that compares them to the block**: rejected as
  a mechanism built to protect a duplicate. The cheaper move is to delete the
  duplicate; a gate here would be the second-best fix to a problem with a
  first-best one.
- **Keep them for template users on Cursor or Codex**: the real cost, accepted
  rather than dismissed. A fork into those editors now runs `deploy-adapters`
  itself — the right default there, since its template has not diverged yet and
  the command is not yet destructive. `docs/FORKING.md` is silent on these
  directories and is not amended: that is the fork's decision, not ours.

## Consequences

- Cursor and Codex sessions in *this* repository get no Aegis instructions. That
  is honest rather than harmful: they also have none of the hooks the instructions
  assume, so a Cursor agent following them could not have satisfied the gates
  anyway.
- The "adapter templates may be outdated" notice will keep appearing on every
  aegis response and must keep being ignored. A notice that must be permanently
  disregarded is a poor state; it is tolerated because the alternative is letting
  a vendor command overwrite hand-edited instructions.
- If the aegis template ever gains something worth having, it is diffed in by
  hand. Nothing automates that, and nothing detects when the template moves.
- `deploy-adapters` recreates the deleted directories. Their absence is therefore
  not self-maintaining, which is why the AGENTS.md section names the command
  rather than only the files.
