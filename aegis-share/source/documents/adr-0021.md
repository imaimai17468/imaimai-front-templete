# 0021. Records live only in the knowledge base; `docs/adr/` and `docs/superpowers/` are removed

- Status: accepted
- Date: 2026-07-29

## Context

Three directories held records of the same kind: `docs/adr/` (decisions),
`docs/superpowers/specs/` (design notes and audit findings) and
`docs/superpowers/plans/` (work plans). `docs/adr/` was additionally mirrored into
`aegis-share/source/documents/`, with AGENTS.md requiring every ADR edit to be
copied across and the share pipeline re-run, and a Stop-gate check watching for
the drift that discipline exists to prevent.

Measured on 2026-07-29: the process apparatus (`.claude/` 5,649 lines,
`docs/adr/` 1,818 lines, AGENTS.md, 34 files under `docs/superpowers/`) was
roughly three times the size of the application it governs (`src/`, 48 files,
2,506 lines), and 58 of the previous 60 non-merge commits touched only the
apparatus. The repository owner's objection was that the structure had become
the product.

ADR-0008 had already considered and rejected exactly the consolidation this ADR
makes — "keep detailed rules on disk, serve them via Aegis only: rejected —
deferred delivery requires readable source files". That premise no longer holds.
`aegis_compile_context` accepts `content_mode: "always"`, which returns every
document's body inline; verified the same day against knowledge_version 120,
where a request with that mode returned all seven matched documents with
content. The rejection was correct about the default and wrong about the tool.

Two further facts settled the mechanics. `aegis_sync_docs` documents
`skipped_invalid_anchor` for "unusable paths (missing, outside project, or
resolve errors)", so a deleted anchor is skipped rather than an error.
`aegis-share/canonical.json` carries each document's full `content`, so the
bundle is self-contained and deleting the anchored file loses nothing.

## Decision

**The knowledge base under `aegis-share/source/` is the only home for records.**

- `docs/adr/` and `docs/superpowers/` are deleted. The 20 ADRs already existed in
  `source/documents/`; nothing else in those trees was a record the project still
  acted on. `specs/` is **not** a record location and stays: a
  `specs/<feature>.spec.md` is a working file a task writes, verifies and then
  implements against, like the eval fixtures. Only its `README.md` is removed,
  because that was format documentation and now lives in the `verify-spec` skill.
- Every document becomes `ownership: standalone` with no `source_path`. Nothing
  anchors them any more, because nothing outside the knowledge base holds their
  text. Two other options were tried first and rejected by measurement: leaving
  the anchors pointing at the deleted `docs/adr/` paths makes every sync report
  `skipped_invalid_anchor`, and re-anchoring each document to its own
  `source/documents/adr-NNNN.md` makes all 21 permanently stale — that file
  carries frontmatter the stored body does not, so the hashes can never agree,
  and `aegis_sync_docs` opened an update proposal on the first document tried.
  A `doctor` that always reports attention is not a check (ADR-0013).
- Relative cross-links between ADR bodies (`](0015-flat-review-pipeline.md)`)
  became plain `ADR-0015` text. They only resolved while the files sat in one
  directory, and a link is navigation, not a claim.
- The Stop-gate Aegis check now watches `aegis-share/source/` instead of
  `docs/adr/`. Its subject moved; the failure it catches — editing the source and
  forgetting the pipeline — did not go away.
- The eval fixtures moved to `scripts/evals/`. They are patches and expected
  outputs, not records, and `scripts/` already holds their runners.
- `docs/adr/README.md`'s durable content — when an ADR is warranted, the
  MADR-lite skeleton, and the numbering rules — moved into AGENTS.md as
  "ADR form". Its index is not reproduced: the knowledge base is the list.
  `specs/README.md`'s spec skeleton moved the same way, into the `verify-spec`
  skill's own **Format** section, since that skill is its only consumer. The
  directory itself keeps its role — `start-workflow` step 4 still writes there.
- **Retired decisions stop being served.** Seven edges pointed at the four ADRs
  with no live decision (0001, 0003, 0009, 0010) and are removed: `review` and
  `.claude/hooks/**` reached 0009 while already reaching its successor 0011;
  `refactor` and `scaffold` reached 0003 alongside 0012; `specs/**` and `scaffold`
  both reached 0010, whose spec-verification mandate is stated unconditionally in
  AGENTS.md's Workflow section and gated by `start-workflow` step 4, so both edges
  were redundant rather than load-bearing — not removed because the path went away,
  since `specs/` stays; and `src/**/*` reached 0001 — the history of where rule
  files used to live, which a `src` edit does not need. The
  documents stay (numbering is never reused), but nothing resolves to them, so
  compiling context no longer hands the reader a decision that was replaced. It
  did before: a `review` compile on 2026-07-29 returned adr-0009's full body at
  relevance 0.56.
- **Work findings are not persisted.** `repo-audit`'s "Work" lane reported to
  `docs/superpowers/specs/`; with that directory gone the lane now reports to the
  user in the audit summary. Routing it into the knowledge base was considered and
  rejected — ADR-0008 item 2 restricts the KB to decisions and this ADR keeps that
  item, every document is `kind: reference`, and the plan directories were deleted
  because nothing had been acting on them.

This amends ADR-0008: decision item 2 ("the KB carries ADRs only") stands, and
its rejected "serve via Aegis only" alternative is now the chosen design.

## Alternatives considered

- **Keep `docs/adr/` as the source and drop the `aegis-share/` pipeline**:
  rejected by the owner, who asked for the knowledge base to be the single home.
  It would also give up Aegis's relevance-ordered serving for a plain directory.
- **Keep both copies and live with the mirror discipline**: rejected — it is the
  status quo, and the Stop-gate check existed only because the discipline is
  forgettable.
- **Delete Aegis instead, and keep plain files**: proposed during the same
  session on the evidence that ten consultations had returned nothing unique.
  Withdrawn: that run passed `intent_tags: []` against an empty tag catalog and
  never requested inline content, so it measured a misconfiguration rather than
  the tool.

## Consequences

- One place to edit a record, and the share pipeline is the only step that can
  be forgotten. `doctor` reporting in_sync remains the check.
- A human browsing the repository no longer finds ADRs by reading a directory;
  they read `aegis-share/source/documents/` or ask Aegis. The frontmatter makes
  those files less pleasant to read than the ones they replace.
- `expanded` context is still inert: `manifest.json` records
  `includes_tag_mappings: false`, so `aegis_get_known_tags` returns an empty
  catalog and tag-driven expansion cannot fire. That is now the largest unused
  half of the tool, and it is a setup gap rather than a design decision.
- Older ADR bodies still describe paths that no longer exist (`docs/adr/`,
  `docs/superpowers/specs/`). Those sentences record where things were when the
  decision was made and are deliberately not rewritten; this ADR is the note
  that explains them.
