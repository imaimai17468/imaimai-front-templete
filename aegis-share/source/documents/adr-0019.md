# 0019. The review is one pass: find → verify → fix → done

- Status: accepted
- Date: 2026-07-28

## Context

ADR-0013 made any `Edit`/`Write`
clear `.claude/.review-stamp`, so fixing a finding required reviewing again
before committing. That closed a real hole — the old stamp proved only "a review
happened at some point" — and it was judged affordable because
ADR-0011 had dropped a review
to two agents.

The cost was then measured and found high, not affordable:
ADR-0014 recorded re-reviews
re-reading the full diff and re-running whole-project verification the parent had
already run (~40–105k tokens, 1–5 min per run). Its remedy was to make the second
review cheap (delta mode, −62% tool uses) rather than to remove it.

Two sessions of operating that answer show it does not hold:

- **Delta mode does not get used.** It is an instruction, not a mechanism.
  On 2026-07-28 the parent ran full-mode re-reviews instead, and separately
  fixed findings before dispatching the verifier — which broke the diff-hash
  pairing and cost an entire extra find+verify pair. Both are the failure mode
  ADR-0001 named: guidance that depends on the agent choosing to follow it.
- **The user experience is the loop, not the token count.** What the repository
  owner reported was watching the verifier start again after every fix. A
  procedure with a return arrow reads as unbounded even when each iteration is
  cheap, and it makes the reviewer feel like a toll rather than a check.

Meanwhile the exposure ADR-0013 was closing is now covered from other
directions. The Stop gate runs typecheck / lint / format / knip / similarity on
the post-fix tree; lefthook checks staged files with `--check` only, precisely so
the committed bytes equal the reviewed bytes; CI re-runs typecheck, lint, format,
knip, test and build on the PR (not similarity — that check is local-only); and
an independent PR-side AI reviewer (cubic) reads the final diff — including the
fixes — before merge. What a second local review adds is judgment on the fix
itself, and only that.

## Decision

The pre-commit review is **one pass: find → verify → fix → done**. Fixing what
the verifier confirmed does not trigger another review — `post-edit-check.sh` no
longer clears `.review-stamp`, so those edits keep it and the parent commits
next. This amends ADR-0013's review-gate bullet; the rest of ADR-0013 (gates as
deterministic artifacts) is untouched, and this is deliberately a return to
ADR-0009's original reasoning, which rejected
diff binding because "strict diff binding would force a re-review after every
fix".

Removing the per-edit clear takes away more than the loop: that clear was also
what stopped one task's stamp from authorising the next task's commit. The first
draft of this ADR claimed the remaining clears (a `code-reviewer` dispatch, an
aegis cycle) covered that, "which every new task must run" — an instruction, not
a mechanism, and the review of this very change reproduced the hole end-to-end:
task A reviewed, fixed and committed, then an unrelated never-reviewed task B
committed on task A's stamp, because a parent implementing directly (ADR-0012)
triggers neither clear. One mechanism replaces it:

**A commit that leaves the working tree clean consumes the stamp**
(`post-bash-stamp-consume.sh`). One review still covers a multi-commit split,
because the tree stays dirty between partial commits; once the reviewed batch is
fully landed, the stamp has nothing left to authorise and the next task starts
without one.

Two properties are unchanged: the `.finder-done` diff-hash marker from
ADR-0015 still means editing *between* the two
dispatches yields no stamp and a lone verifier cannot stamp, and the two
pre-existing clears still fire.

**Delta mode is deleted**, not demoted. It existed to make the second review
cheap; with no second review it is dead weight, and a mode that must be
remembered is the failure mode this ADR is correcting. `review-diff` now has one
mode, and the `mode` / `fallback` fields are gone from the finder and verifier
output contracts.

**Residual gap, stated rather than papered over.** No hook can decide "is this a
new task", so the mechanism keys on the observable proxy instead. A task boundary
crossed with leftover dirt in the tree (a scratch file, a deliberately deferred
hunk, an early draft of the next task) never reaches "clean", so the stamp
survives it and the follow-on work can commit unreviewed. The exposure is one
task deep and requires the parent to also skip the Aegis consult AGENTS.md
mandates. A scope check on the stamp would narrow it, and was built and then
removed during this change: it blocked a fix that *added* a file, which is a
re-review by another name and therefore the thing being removed. Narrowing this
gap is only worth doing with a mechanism that never blocks a fix.

`scripts/test-review-gate.py` drives these sequences against the real hooks in a
throwaway repository, so the behaviour above is executable rather than asserted.
Run it after touching `pre-bash-guard.sh`, `post-agent-review-stamp.sh`, or
`post-bash-stamp-consume.sh`.

## Alternatives considered

- **Keep the loop and actually use delta mode**: rejected by the repository
  owner after the cost was explained. It also leaves the mechanism resting on
  the agent remembering to pick the cheap mode — the thing that already failed.
- **Re-run only the verifier on the fix (three agents)**: rejected — it is still
  a return arrow, which is what the owner objected to, and it would require
  loosening the ADR-0015 pairing invariant that makes the stamp meaningful.
- **Keep clearing, but only for edits outside the confirmed findings' files**:
  rejected — "was this edit part of the fix" is not decidable by a hook, and a
  gate that guesses is worse than one that is explicit about what it does not
  check.
- **Record the reviewed file scope in the stamp and block commits that grow it**:
  built during this change, then removed. It narrows the residual gap below, but
  a fix that extracts a helper into a new file is an ordinary fix, and blocking
  it is a re-review wearing different clothes.
- **Match the commit gate against a diff hash taken at stamp time**: rejected —
  it re-blocks after every fix, which is the loop verbatim. ADR-0013's own
  Alternatives had already rejected it for a different reason (multi-commit
  splits move `git diff HEAD`).
- **Record post-review edits in an artifact and disclose them at commit time**:
  rejected for now — it is a warning, and ADR-0013 already established that a
  warning the agent may ignore is not a gate. Revisit if fixes are found to
  introduce defects in practice.

## Consequences

- A review costs two agents, once, per commit. The return arrow is gone from
  AGENTS.md, `review-diff`, `start-workflow`, and `docs/agent-workflow.md`.
- **The fix itself is no longer judged by a fresh context.** This is the
  accepted risk, and it has a recorded precedent: the 2026-07-25 audit's S0
  entry describes a first fix that was incomplete (it passed the secret but left
  the absent case silent) and was caught by exactly the re-review this ADR
  removes. The mitigations are the Stop gate, CI, and the PR-side reviewer —
  none of which reason about intent. Fixes that are more than mechanical should
  therefore be re-reviewed by choice.
- Ordering discipline matters more than before: the only edits the stamp
  survives are the ones made *after* the verifier returns. Editing between
  finder and verifier still costs the whole pass.
- This amends ADR-0014's second
  decision, which added delta mode; that mode is now deleted. Its fixture and
  measurements in `scripts/evals/review-diff/` are kept as the record of
  why it existed, and are no longer exercised.
- ADR-0014's eval obligation covers "any load-bearing edit to `review-diff`".
  Nothing here changes how the finder or verifier judge a diff — the judging
  logic in Steps 1 and 3 is untouched, and only the output envelope in Steps 2
  and 4 lost the `mode` / `fallback` fields — so a scored run would reproduce the
  existing scores.
  Deleting a mode removes a code path rather than adding one to measure. No eval
  run was made; that is a scoping judgement, recorded so it can be disputed
  rather than discovered.
- Fixes that are more than mechanical now land unjudged by design. If that turns
  out to cost defects, the honest next move is the one the owner suggested during
  this change: make the single pass produce the fix — have the verifier return
  the concrete change and its acceptance check for each surviving finding — so
  the judgement happens inside the pass instead of after it.
