# 0025. The per-edit lint hook is removed; lint lives at commit, push and CI

- Status: accepted
- Date: 2026-07-31

## Context

`post-edit-check.sh` ran on every `Edit`/`Write`/`MultiEdit`, linting the one file
just written with `bunx oxlint --type-aware` and blocking the next tool call on
failure. It was the first of four layers running the same linter: `lefthook.yml`
lints staged files at pre-commit and runs `bun run check` whole-project at
pre-push, `stop-gate.sh` runs it at the end of a turn, and `ci.yaml` runs it on
every push to `main` and every PR.

So the hook did not decide whether a lint error reaches `main`. What it bought was
latency: a failure surfaced while the edit was still in context instead of at
commit time, when several files' failures arrive together.

What it cost was a `bunx` invocation per edit, and blocking on states that are
legitimately broken mid-change. That cost was already paid down once: the hook
originally ran whole-project checks, and was narrowed to the single edited file
because running them per edit "re-checked the world N times per task and blocked
legitimate mid-refactor states" (its own comment). The narrowing reduced the
problem without removing it — a multi-file refactor still trips it between the
first edit and the last.

The repository owner asked for it to go.

## Decision

Delete `post-edit-check.sh` and its `PostToolUse` registration. Lint runs at
pre-commit (staged files), pre-push (whole project), the Stop gate, and CI.

This amends **ADR-0012**, whose Context cites "the per-edit lint hook and the
review gate moved the quality argument" as part of why the parent implements
directly rather than delegating for quality reasons. One of those two mechanisms
is now gone. The decision stands: the review gate — a fresh-context finder and
verifier the parent cannot talk past — is the load-bearing half, and the three
remaining lint layers all sit between an edit and `main`. What changes is that
nothing corrects the parent mid-task, so `start-workflow` step 6's own checks
matter more, and the skill now says so instead of pointing at a hook.

`scripts/test-review-gate.py` drove this hook so that its "a fix needs no second
review" assertions ran through the mechanism that had once cleared the stamp on
every edit (ADR-0013, removed by ADR-0019). With no hook to drive, `edit()` is a
plain write. The suite therefore can no longer detect a *future* hook that starts
clearing the stamp on every edit; the helper carries that warning, because the
assertion would silently pass for the wrong reason.

## Alternatives considered

- **Keep it for feedback latency**: rejected by the owner. The argument is real but
  it is a convenience, not a guarantee, and it is the only thing the hook provided.
- **Keep it non-blocking (warn instead of block)**: rejected — ADR-0013 established
  that a warning the agent may ignore is not a gate, so this would keep the
  per-edit cost while dropping the one property that made the cost defensible.
- **Widen it to typecheck as well**: rejected — the opposite direction. Whole-project
  typecheck per edit is what the original narrowing removed.

## Consequences

- A lint error now surfaces at the first of pre-commit, the Stop gate, or CI,
  whichever the session reaches first — later than before, and in batches.
- Editing many files no longer pays a `bunx` start per file.
- `PostToolUse` has three registrations left, all of them Aegis- or gate-related.
  No hook fires on an edit at all, which is worth knowing before assuming an edit
  is checked by something.
- Nothing in the enforcement layer now depends on a `PostToolUse(Edit|Write)`
  registration existing, so re-adding one is a fresh decision rather than a
  restoration.
