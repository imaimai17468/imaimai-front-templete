# 0030. AGENTS.md carries directives; rationale, procedure and troubleshooting move out

- Status: accepted (amended by 0031)
- Date: 2026-08-07

> **Note (ADR-0031, 2026-08-07):** the Decision item "`.claude/rules/` is not
> extended" no longer holds. The loader bugs it cited did not reproduce on
> Claude Code 2.1.223 in a local sentinel test, and the Aegis process block —
> which this ADR kept in AGENTS.md — moved to `.claude/rules/aegis.md`
> (`alwaysApply: true`), mirrored into `.cursor/rules/` as file-level symlinks.
> Everything else in this ADR stands: directives-only AGENTS.md, the four-kind
> sort, and the removal rule.

## Context

AGENTS.md is the single always-on instruction file (ADR-0008) and had grown to
234 lines / 29 KB, loaded in full into every session. Two sections held 58% of
it: `## Agents` at 9,544 bytes and `## Aegis Process Enforcement` at 7,496.

Most of that weight is not instruction. It is recorded reasoning — why a
decision was made, what was measured, which sentence was written false and
caught in review — plus operational troubleshooting for situations most
sessions never reach. AGENTS.md's own "Instruction documents" rule says to point
at other files rather than restate them, and the file had become its own largest
violation: the "Permission mode" section restates ADR-0004's 2026-07-28
amendment, the "Review" paragraph restates ADR-0029 and the preloaded
`review-diff` skill, and "Aegis adapter templates" restates ADR-0026.

ADR-0008 solved this shape once for a different file set — seven always-on rule
files became condensed AGENTS.md sections — and its 2026-07-25 amendment records
the two that came back, path-scoped rather than always-on.

## Decision

**Content is sorted by kind, and AGENTS.md keeps only one of the four kinds.**

1. **Directives** — what to do, applying whenever they apply — stay in AGENTS.md.
2. **Rationale** — why a decision was made — becomes a pointer to the ADR that
   holds it.
3. **Procedure and troubleshooting** — needed only while carrying a step out, or
   when it has gone wrong — moves to a skill. `write-adr` takes the MADR-lite
   skeleton, the numbering rules and the ~80-line budget; `aegis-ops` takes
   compile troubleshooting and the `compile_miss` payload.
4. **Rules scoped to particular files** are reached through Aegis path edges
   instead of being restated.

**A paragraph is removed only when a live ADR or skill already holds its
content, confirmed by opening that file in the same change.** Where nothing held
it, the content moved first: `permissions.defaultMode: "auto"` being ignored in
project settings was the one fact in the "Permission mode" section that ADR-0004
lacked, and it became an ADR-0004 amendment before AGENTS.md lost it.

**`.claude/rules/` is not extended.** Adding path-scoped rule files for ADR form
and agent configuration was the obvious route and is rejected twice over. Claude
Code has open bugs in that mechanism — rules with `paths:` not loading for
matching files ([#16853](https://github.com/anthropics/claude-code/issues/16853))
and loading globally regardless of `paths:`
([#16299](https://github.com/anthropics/claude-code/issues/16299)) — so a MUST
placed there could be silently absent or silently always-on, the "gate silently
off" failure ADR-0013 exists to prevent. Independently, the text needed no new
home: ADR-0004 and ADR-0014 already held it. What was missing was reach.

**Reach is fixed with edges, not copies.** `.claude/agents/**` and
`.claude/settings.json` gain edges to ADR-0004; before this change neither
reached it and its only path edge came from `src/**/*`. AGENTS.md gains an edge
to this ADR. Each passes ADR-0023's reach test.

## Alternatives considered

- **Compress the prose in place and move nothing**: rejected. The conditional
  sections stay in the always-on budget, and a restatement left next to what it
  restates keeps drifting from it.
- **Reduce AGENTS.md to an index of 2–4 line sections**: rejected. Its value is
  that it is read without being sought. A MUST behind a pointer depends on the
  agent choosing to follow the pointer, and this project's recorded failures are
  mostly agents not knowing to look.
- **Keep every war story in AGENTS.md**: rejected as the default, kept as a
  test. A recorded mistake earns always-on weight only where the directive alone
  would not prevent it.

## Consequences

- AGENTS.md drops from 234 lines to roughly 100, and what remains is
  unconditional. Sessions that never write an ADR or hit a failing compile no
  longer carry the instructions for either.
- Rationale now takes one hop. When Aegis is unavailable, the degraded path —
  reading `aegis-share/source/documents/` directly — is what supplies it, which
  AGENTS.md already requires for every consultation.
- The `aegis:start`/`aegis:end` block shrinks, so a `deploy-adapters` run
  destroys less of this project's own text if one happens despite ADR-0026.
- **The failure mode is a pointer to a record that no longer says what the
  pointer claims, and nothing checks that.** The counterweight is the removal
  rule above: the destination was opened as the pointer was written. This is
  weaker than a gate and is accepted as such.
- ADR-0004 gained an amendment as a side effect of an AGENTS.md change rather
  than from a permissions decision. That is the intended direction — a fact
  belongs with the decision it qualifies, not with the file that noticed it.
